## V4.1 Homogeneous-length batches; no padding

This section replaces every v2/v3 implication that examples of different `n`
share a model batch. No model input is ragged or padded.

For training step `t`, the already frozen per-step PCG64 stream first draws one
`n = integers(4,9)`. Every candidate example drawn for that step is conditional
on that one `n`; collect 32 examples per quadrant and apply the frozen final
batch permutation. The resulting model tensor has shape `128 x (n+1) x 14`.
The next random draw after `n` is the first example's `q`; per-example `n` draws
from v2 are removed. Across steps, `n` is iid uniform over 4--8 and is paired
byte-for-byte across architectures.

The in-support development fixture at seed `841100` is five separately stored
length buckets in ascending `n=4,5,6,7,8`. Each bucket contains exactly 2,000
examples, 500 per quadrant, generated by continuing one PCG64 stream and then
permuted within that bucket. Development error is total mistakes divided by
10,000; model calls never combine buckets.

The v3 probe corpus at seed `840190` is likewise five separately stored buckets,
each containing exactly 20,000 examples, 5,000 per quadrant. The feature probes
may concatenate their fixed-size summary vectors after extraction, but no token
model receives mixed-length examples. Main ID/OOD slices already have fixed
`n`. Padding values, padding tokens, and padding masks remain forbidden.

## V4.2 Restored tied time-control operator

V3.2 replaces timing orchestration only; it does not replace this operator
definition from v2. For each selected pair `(r_attention,r_ffn)` and each of the
two parameter-untied blocks, execute the following with weights tied across
repetitions inside that block:

1. repeat `h <- h + Attention(RMSNorm_attention(h), mask)` exactly
   `r_attention` consecutive times, recomputing norm, Q/K/V, scores, reducer,
   group RMS, and `W_O` each time;
2. then repeat `h <- h + FFN(RMSNorm_ffn(h))` exactly `r_ffn` consecutive
   times, recomputing norm and FFN each time;
3. move to the next block.

Block 0 and block 1 never share parameters. The ordinary candidate and all
non-time controls use one attention and one FFN application per block.

## V4.6 Non-overlapping resource and artifact accounting

This section replaces V3.3's accounting mechanics while retaining its included
work list and numeric ceilings.

Only top-level authorized controller invocations contribute elapsed time. For
each invocation, add exactly once `CLOCK_MONOTONIC_after -
CLOCK_MONOTONIC_before`, measured before its first charged action and after its
last artifact fsync/hash. Child-worker lifetimes and diagnostic CPU times are
reported but never added separately. Controllers and workers are sequential;
no two authorized invocations overlap. Audit/idle gaps between invocations are
not charged. The cumulative SHA-256 hash-chained duration ledger must remain at
or below eight hours.

All run outputs and temporary files live in one new append-only run directory.
Deletion, truncation, hard links, sparse files, and outputs elsewhere are
forbidden. After each fsync, artifact usage is the recursive sum of
`st_blocks*512` for every regular file in that directory; it must remain at or
below 2 GiB. Logical `st_size` is also reported. Absolute Linux `VmHWM` is
recorded for controller and every worker; the maximum must remain at or below
2 GiB and is never baseline-subtracted. A killed/incomplete controller lacks a
valid closing ledger receipt and is `PROTOCOL INVALID`, not replayed.
