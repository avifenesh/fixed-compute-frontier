# Reversible slot-grammar plane T33 — adversarial paper audit

Status: **PASS ONLY TO FROZEN B0--B3 CPU CENSUS**  
Date: 2026-07-31

## Verdict

The first draft was not executable: its recovery assumptions allowed
positive-saving spurious pair templates, its document-subject normalization
could create a universal shortcut, and its coverage equation ignored existing
shortcut accuracy.  Those claims were corrected before code or data access.

The corrected paper has a valid restricted recovery theorem and an exact
failure surface.  It admits one CPU census because that census can answer the
next fatal question without model training:

> Does the frozen raw corpus contain enough unambiguous recurring one-hole
> surface programs to put a witnessed pointer inside at least 89.44% of the
> two-record support sentences, within the sidecar budget?

A pass would establish structure availability only.  It would not establish
semantic question mapping, a smarter model, novelty over grammar indexes, or
serving noninferiority.

## Corrections made by the audit

1. Added **proposal isolation**.  Boundary diversity recovers a true template,
   but does not stop a broad cross-relation or narrow within-value proposal
   from conflicting with it.
2. Replaced the implicit-subject `DOC` prefix with reversible replacement of
   exact own-title surfaces by `SELF`.  The document container remains an
   external address and makes no grammatical assertion.
3. Replaced the additive accuracy expression by a shortcut-conditioned upper
   bound.  The 89.44% threshold is explicitly a conservative structure-alone
   design gate, not a necessary bound on final accuracy.
4. Declared the query-mapper table and arbitrary-ID difficulty as charged
   resources rather than assuming a free 4,096-way classifier.
5. Acknowledged that a grammar self-index with the same rule dictionary can
   reproduce the logical function.  T33 can claim only exact acquisition and a
   possible materialized byte/latency point.

## Why the theorem is now valid

The family assumes one-hole programs `a_r + value + b_r`, recurrence,
boundary-diverse values, cross-rule separation, one unambiguous event per
admitted sentence, positive two-part-code gain, and isolation from every other
eligible pair proposal.  Under those assumptions:

- a boundary-diverse pair proposes exactly `(a_r,b_r)`;
- separation gives the exact occurrence set;
- proposal isolation removes conflicting accidental templates;
- exact substitution recovers every source sentence;
- a later one-shot value is assigned by an exact match.

These conditions are strong but raw-observable through recurrence, matching,
conflict, and reconstruction.  Semantic utility is deliberately deferred to a
sealed evaluator.

## Remaining risks that do not invalidate a CPU census

- Proposal isolation may reject nearly everything in real prose.
- Exact surface recurrence may capture boilerplate rather than facts.
- Replacing only exact own-title mentions misses aliases and pronouns.
- A middle span can be structurally valid but omit the answer-bearing value.
- Natural questions can remain disconnected from declarative rule anchors.
- The dictionary and edge arrays can cost more than a direct scan saves.
- Branchy indexed reads can be slower than dense GPU work.

Each risk has a later kill gate.  None is a reason to train first.

## Strong-control conclusion

There is no universal function-class separation.  A sufficiently general
conditional memory can store the same edge table, and a grammar self-index can
compute the same hole extraction.  The possible edge is the conjunction of:

1. raw-only deterministic acquisition rather than gradient memorization;
2. exact one-shot bindings into a shared surface program;
3. low-bit pointers into a lossless base;
4. a learned query mapper that generalizes to natural questions;
5. a complete served byte/work point better than all alternatives.

If the first three do not exist at high coverage on the raw corpus, the last
two are irrelevant.  This justifies B0--B3 as the next decision-efficient test.

## Admission

Write and hash a preregistration before implementation.  The executable stage
must:

- read only the raw candidate corpus while constructing rules;
- use exhaustive small-world checks for anti-unification and recovery;
- reject every conflicting positive-saving proposal without heuristic choice;
- freeze the rule/edge object before opening support metadata;
- report support-sentence edge coverage separately from semantic sufficiency;
- stop before any mapper, model, embedding, or GPU work on failure.
