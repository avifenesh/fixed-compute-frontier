# Cross-instance moment bridge T26 — paper audit

Status: **NOT ADMITTED; EVENT SELECTION IS CIRCULAR**  
Date: 2026-07-31

## Proposed bridge

Use repeated corpus-wide incidence rather than same-sentence augmentation.  For
each relation-bearing event, expose three raw views `X1`, `X2`, and `X3` and a
latent relation `R in {1,...,K}`.  Under conditional independence,

\[
P(X_1,X_2,X_3)
=\sum_{r=1}^K \pi_r
  P(X_1\mid r)P(X_2\mid r)P(X_3\mid r).
\]

Writing the view probability vectors as `a_r`, `b_r`, and `c_r`, the observable
third moment is

\[
T=\sum_{r=1}^K \pi_r,a_r\otimes b_r\otimes c_r.
\]

The recovered component index would become the discrete relation code.  A
document would store exact `(entity, relation, value)` records, and a query
would map into the same component basis.  The existing exact digital read plane
would provide storage only after this bridge passed.

## What the algebra genuinely proves

A matrix with two views has a change-of-basis ambiguity: for invertible `S`, a
factorization can be transformed by `A -> AS` and `B -> B S^-T` without
changing the matrix.  A third view can remove that continuous ambiguity.

Under standard CP uniqueness conditions—for example, Kruskal ranks satisfying

\[
k_A+k_B+k_C\ge 2K+2,
\]

the rank-one components of `T` are unique up to a shared permutation and
component scaling.  Probability normalization fixes the scaling; the
permutation is harmless because writer and reader can share it.  Observable
moments can therefore identify a finite latent relation variable under the
declared multi-view mixture model.  Robust constructive tensor methods for
this family are established in
[Anandkumar et al.](https://jmlr.org/papers/v15/anandkumar14b.html).

The corresponding counterexample is also clear.  If two relation components
have identical columns in enough views, or if the required rank condition
fails, multiple latent decompositions induce the same raw distribution.  No
optimizer can recover which relation assignment generated the data.

## The fatal missing map

The theorem starts **after** a relation-bearing event and its three views have
been selected.  Arbitrary raw prose supplies only a token sequence.  It does
not mark:

- which spans are entities or values;
- which ordered entities participate in a fact;
- which tokens express the relation rather than topic, style, negation, or a
  different fact;
- where one event ends and another begins;
- whether two mentions of one entity pair express the same relation.

Exact corpus-title matching can identify some entity strings, but it does not
identify common-noun values, pronouns, direction, scope, or relation spans.
Restricting to a hand-written `title is a noun phrase` schema would make a
useful narrow extractor, not an autonomous raw-prose compiler for a production
language model.

## Why obvious view constructions do not repair it

### Randomly partitioning one sentence

Splitting tokens into left/center/right or three random bags does not make the
views conditionally independent given semantic relation.  They continue to
share sentence identity, topic, syntax, author style, other facts, and local
lexical choices.  The tensor may identify a surface/topic mixture while fully
satisfying its numerical decomposition objective.

### Repeated entity pairs

The same ordered entity pair can express many relations, and most long-tail
facts appear only once.  Pair identity is therefore neither a relation label
nor three independent views.  Treating it as one silently assumes the desired
semantic grouping.

### Enumerating every window or span

Enumeration avoids choosing one span but creates a dominant nuisance/noise
mixture and does not specify which recovered components are facts.  A theorem
would need identifiable separation of relation events from all enumerated
non-events.  No such separation or rank margin has been supplied.

### Treating a natural question as another view

The fitted raw-prose model contains no question-conditioned emission matrix.
The tensor theorem maps a new observation only when it is generated by a known
view model.  Assuming that interrogative and declarative surfaces share the
same conditional word distribution is false in general.  Learning a separate
question map from labels violates the raw-only bridge contract; asking an
ordinary Transformer to infer it leaves a second unisolated semantic miracle.

## Gate result

| Stage -2 gate | Result |
|---|---|
| S0 generative family | valid only after privileged event/view selection |
| S1 recovery theorem | pass for the conditional multi-view mixture |
| S2 counterexample | pass: rank/view collision is explicit |
| S3 unseen-query theorem | fail for natural questions |
| S4 resource ledger | premature because raw event count/representation is undefined |
| S5 breakthrough derivation | fail: no bound connects recovered components to target capability |

The candidate has more than one empirical unknown: event discovery, component
semantics, and query alignment.  Training would conflate all three.

## Decision

Do not implement a tensor decomposition, topic model, NMF sweep, or H100
experiment for T26.  Such a run would necessarily bake in a hand-selected
window/event schema and then test that schema, not the claimed autonomous
semantic bridge.

Retain the following block:

> Once three genuinely relation-conditioned raw views exist with adequate
> rank, their latent component can be recovered up to a harmless permutation.

The next paper candidate must jointly construct relation-bearing events from
the raw token sequence.  An identifiable grammar or minimum-description-length
program is one eligible evidence source, but it receives no admission from the
valid tensor subtheorem and must begin again at S0.
